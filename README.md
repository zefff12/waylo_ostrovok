# Waylo — ИИ-агент для путешествий (трек «О!дин запрос»)

Пользователь описывает поездку одним сообщением, а Waylo уточняет недостающее, подбирает направление, дорогу и отель, считает бюджет, строит прогулки по дням с картой, проверяет состыковки и доводит до демо-оплаты в профиле.

- Видео-скринкаст: _ссылка будет добавлена_
- Развёрнутый сервис: https://waylo-cfp5.onrender.com (бесплатный тариф Render: после 15 минут без посещений сервис засыпает, первое открытие занимает около минуты)

## Быстрый старт

```bash
git clone https://github.com/zefff12/waylo_ostrovok.git
cd waylo_ostrovok
cp .env.example .env   # ключи необязательны: без них работает агент на правилах
docker compose up --build
# открыть http://localhost:8080
```

Если порт 8080 занят, задайте другой: `APP_PORT=8088 docker compose up --build`.

Без Docker: нужны Python 3.11+ с [uv](https://docs.astral.sh/uv/) и Node.js 18+.

```bash
cd frontend && npm install && npm run build && cd ..
uv run --project backend uvicorn app.main:app --app-dir backend --port 8080
```

Без `DATABASE_URL` данные хранятся в файле SQLite `backend/waylo.sqlite3`.

## Зависимости и переменные окружения

Рекомендованные ресурсы:

- 1 CPU
- 1 GB RAM

Сервисы:

- PostgreSQL 16 (в `docker-compose.yml` как `db`)
- кэш и очереди не нужны

Переменные (полный список с комментариями — в `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | порт на хосте для docker compose |
| `DATABASE_URL` | в compose: `postgresql://waylo:waylo@db:5432/waylo` | база; без неё — SQLite |
| `WAYLO_LLM` | `auto` | нейросеть агента: `gigachat`, `claude`, `offline` или `auto` (первая, для которой задан ключ) |
| `GIGACHAT_CREDENTIALS` | пусто | ключ авторизации GigaChat API |
| `GIGACHAT_MODEL` | `GigaChat-2-Max` | модель GigaChat |
| `ANTHROPIC_API_KEY` | пусто | ключ Claude API |
| `WAYLO_MODEL` | `claude-haiku-5-5` | модель Claude |
| `TRAVELPAYOUTS_TOKEN` | пусто | цены перелётов из кэша Aviasales |
| `DGIS_API_KEY` | пусто | кафе рядом из 2ГИС; без ключа — OpenStreetMap |
| `YANDEX_JS_API_KEY` | пусто | Яндекс Карты; без ключа — OpenStreetMap |
| `WAYLO_HOME_VIDEO` | ролик YouTube | фоновое видео главного экрана |
| `SUPPORT_ADMIN_TOKEN` | пусто | ключ страницы `/support-admin`; без него страница отключена |

Сертификат Russian Trusted Root CA для GigaChat уже лежит в `certs/` и подхватывается сам.

## Сидирование

Таблицы создаются автоматически при первом запуске. Каталог направлений, мест и выгрузка отелей OpenStreetMap лежат в репозитории (`backend/app/data.py`, `data_extra.py`, `hotels_osm.json`) и в базу не загружаются.

Тестовый профиль с двумя сохранёнными пассажирами:

```bash
docker compose exec app backend/.venv/bin/python backend/scripts/seed.py
```

Обновить выгрузку отелей из OpenStreetMap (необязательно, нужен интернет):

```bash
uv run --project backend python backend/scripts/fetch_hotels.py
```

## Маршруты и доступ

- `/` — интерфейс
- `/health` — 200 OK, JSON `{"status": "ok", "db": "postgresql"}`
- `/api/health` — состояние агента и интеграций
- `/support-admin` — ответы на обращения в поддержку, вход по `SUPPORT_ADMIN_TOKEN`
- Тестовый пользователь после сидирования: `demo@waylo.ru / waylo2026`

Основные API: `POST /api/chat` (сообщение агенту), `GET /api/trips/{id}`, `POST /api/trips/{id}/checkout` (только с профилем), `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/me` (поездки, оплаты, пассажиры), `POST /api/support`.

## Как устроено

```
frontend (React + TypeScript + MapLibre)  ──/api──  FastAPI
                                                     ├─ agent_tools.py     11 инструментов агента и системная инструкция
                                                     ├─ agent_gigachat.py  GigaChat (Сбер), вызов функций
                                                     ├─ agent_llm.py       Claude, вызов инструментов
                                                     ├─ agent_offline.py   агент на правилах, если ключа нет или LLM недоступна
                                                     ├─ planner.py         операции над поездкой и журнал изменений
                                                     │   ├─ destinations.py  выбор направления: климат, цена, время в пути
                                                     │   ├─ transport.py     поезд и самолёт
                                                     │   ├─ hotels.py        сравнение отелей
                                                     │   ├─ walks.py         прогулки по дням от отеля
                                                     │   ├─ budget.py        бюджет из позиций
                                                     │   └─ connections.py   прибытие, заселение, трансфер, выезд
                                                     ├─ accounts.py        профиль, сессии, сохранённые пассажиры
                                                     ├─ support.py         обращения в поддержку
                                                     ├─ integrations.py    Open-Meteo, Travelpayouts, 2ГИС, Overpass
                                                     └─ db.py, store.py    PostgreSQL или SQLite
```

Нейросеть понимает запрос, выбирает инструменты и объясняет решения, а цены, время и проверки считает код. Все варианты агента вызывают одни и те же функции, поэтому планы и расчёты совпадают. Факты, которые парсер нашёл в сообщении (город, даты, бюджет, состав, питомцы), важнее аргументов модели: модель не может выдумать бюджет или направление.

## Что умеет

- **Уточняет, а не угадывает.** Если не названы даты, город отправления, состав или бюджет, агент спрашивает и переспрашивает только недостающее, пока не узнает всё или пользователь не ответит «на ваше усмотрение». Ответ «Нижний Новгород. 60000» понимается как город отправления и бюджет.
- **Направление не задано** («к тёплому морю в ноябре, недорого, с ребёнком»): 2–3 варианта с климатом, ценой и временем в пути, у каждого есть «почему», «чем жертвуем» и «риски».
- **Бюджет — жёсткий лимит.** Подбирается лучшая дорога и отель, которые в него помещаются. Если не помещается ничего, агент так и говорит: «с бюджетом N ничего не найдено», называет минимальную цену и предлагает поднять бюджет или сократить поездку.
- **Сравнение отелей** по цене, расстоянию до мест прогулок, отмене, питанию, допуску животных и детей.
- **Проверка состыковок:** раннее прибытие, ночной приезд, вечерний отъезд, питомец в транспорте и отеле, выходные дни музеев. При критичной проблеме оплата блокируется.
- **Правки без поиска с нуля:** «на два дня позже», «бюджет 35000», «бюджет не ограничен», «сделай дешевле», «с нами едет собака», «поменяй отель на подешевле», «на поезде». Каждое изменение попадает в журнал.
- **Прогулки по интересам** с учётом окна дня, обеда и расстояний, маршрут на карте. Правки дня: «меньше ходьбы», «дождь», «заменить на кафе», «добавить музей».
- **Профиль.** Регистрация по почте или телефону с паролем. В профиле хранятся все поездки, оплаты и пассажиры; при оформлении пассажира можно подставить одним нажатием. Без профиля поездку можно собрать, но нельзя оплатить.
- **Оплата (демо):** данные всех путешественников с документом (паспорт, загранпаспорт, свидетельство о рождении до 14 лет) и форма банковской карты. Номер карты не покидает браузер, деньги не списываются. После покупки можно отдельно оплатить ранний заезд и трансфер.
- **Поддержка:** обращения с перепиской, ответы — на `/support-admin`.
- **Память:** последняя поездка, переписка и черновик поиска сохраняются в браузере и восстанавливаются после перезагрузки.
- **Прозрачность:** кнопка «Что сделал агент» показывает вызванные инструменты и их результаты.

## Какие данные реальные

У каждой цены в интерфейсе есть бейдж с её типом, источник виден при наведении.

| Данные | Источник | Тип |
|---|---|---|
| Прогноз погоды (до 16 дней) | Open-Meteo Forecast | реальные |
| Погода на дальние даты | Open-Meteo Archive, те же даты прошлого года | оценка |
| Климат месяца для выбора направления | Open-Meteo Archive | реальные (архив) |
| Цены перелётов | Travelpayouts / Aviasales Data API | оценка: кэш поисков |
| Перелёты без токена, поезда | расчёт по расстоянию | демо |
| Отели: название, тип, звёзды, адрес, координаты, сайт | OpenStreetMap (~60 на город) | реальные |
| Цена отеля за ночь | уровень цен города, звёзды, удалённость, сезон | оценка |
| Отмена, питание, рейтинг отеля | в OSM не публикуются | демо |
| Места для прогулок | ~300 мест в 39 направлениях | названия реальные, часы не подтверждены |
| Кафе рядом | 2ГИС Places API или OSM Overpass | реальные |
| Питание, билеты, такси, транспорт по городу | средние ставки по городу | оценка |
| Карта | Яндекс Карты или OpenStreetMap через MapLibre GL | реальные |
| Оплата и бронирование | — | только имитация, номер `WAYLO-DEMO-…` |

## Результаты проверки

`eval/run_eval.py` прогоняет 34 тестовых запроса, отчёт — в [eval/results.md](eval/results.md):

```bash
uv run --project backend python eval/run_eval.py          # агент на правилах
uv run --project backend python eval/run_eval.py --llm    # нейросеть из WAYLO_LLM
```

С агентом на правилах: проверки пройдены 34/34, до плана или оплаты доведено 26/26 сценариев, где это ожидается, медиана времени до первой рекомендации — около 0,5 с (на GigaChat-2-Max — 10–20 с). Четыре «критичные проблемы» в отчёте ожидаемы: три запроса, где бюджета заведомо не хватает (агент отвечает «ничего не найдено»), и Калининград с собакой — туда в каталоге только самолёт, поэтому оплата блокируется до уточнения правил авиакомпании.

## Известные ограничения

- В каталоге 39 направлений: 23 в России и 16 за рубежом. Про другие города агент говорит, что их нет в каталоге.
- Цены отелей — оценка, условия отмены и питание — демо: открытого API с ценами и наличием нет. Цены поездов синтетические.
- Часы работы мест не проверяются, у платных мест стоит пометка «проверьте на сайте».
- Публичный Overpass бывает недоступен: ожидание ограничено 4 секундами, затем используется локальный набор мест.
- Агент на Claude не проверялся на живом API.
- Бесплатная база PostgreSQL на Render удаляется через 30 дней после создания.
